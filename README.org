#+TITLE: Personal Nixpkgs
#+AUTHOR: Lingyu Ren

* Introduction
A shared foundation for my Nix flake-based projects, intended to be added as a
flake input where needed for cross-repository functions and conventions.
The name reflects its role in this project ecosystem and continuity with the
repository's original use as a personal NUR repository.

* Flake infrastructure
The root flake consumes =pkgs/= as a local subflake named =local-nixpkgs=.
That subflake uses flake-parts to assemble the shared library, package sets and
the =mkFlake= wrapper before the root flake calls that wrapper. Its =nixpkgs=,
=flake-parts= and =treefmt-nix= inputs follow the root's corresponding inputs.

The source is organized as follows:

| Path | Purpose |
|------+---------|
| =flake.nix= | Consume the shared foundation, select public library exports, forward packages and assemble repository checks. |
| =pkgs/flake.nix= | Assemble the foundation and define =lib.mkFlake=. |
| =pkgs/lib/= | Shared merge, package/module discovery and test-assembly functions. |
| =pkgs/pkgs/= | Package definitions and their internal overlay groups. |
| =pkgs/modules/fp/= | Shared flake-parts modules, currently treefmt configuration. |
| =tests/= | Library suites, independent test-assembly acceptance cases and fixtures. |

The root exports =lib=, =packages=, =legacyPackages=, =devShells=, =formatter=
and =checks=. Its public =lib= contains =mkFlake=, =mergeAttrsRecursive=,
=packages= and =tests=.
The subflake's library additionally contains =overlays.mkOverlays= for internal
use, including the generic overlay suite; the root does not export that entry.

** Shared flake construction
=lib.mkFlake= takes three positional arguments:

#+begin_src nix
inputs.personal-nixpkgs.lib.mkFlake inputs.nixpkgs
  ({ lib }: {
    inherit inputs;
    moduleLocation = __curPos.file;
    llib = inputs.personal-nixpkgs.lib;
    lpkgs = inputs.personal-nixpkgs;
  })
  ({ ... }: {
    systems = [ "x86_64-linux" ];
    perSystem.treefmt.settings.excludes = [ "flake.lock" ];
  })
#+end_src

The first argument is the Nixpkgs input used to instantiate per-system packages.
The second is a function receiving ={ lib = nixpkgs.lib; }= and returning the
arguments for flake-parts. Its result must be an attribute set containing
=inputs= and =moduleLocation=; an explicitly supplied =specialArgs= must also be
an attribute set. The third argument is the caller's flake-parts module.
The caller chooses the supported =systems=.

The argument function may supply =llib= and =lpkgs=, both defaulting to ={ }=.
The wrapper removes these two fields from the forwarded flake-parts arguments
and injects them through =specialArgs=, together with =lib = nixpkgs.lib=.
Caller-supplied =specialArgs= recursively override those defaults. This does not
implicitly extend the =lib= argument with =llib=.

The wrapper declares =perSystem.nixpkgs.overlays= as a list of overlays and uses
it to import Nixpkgs for each system, forcing that result as the per-system
=pkgs= argument. The foundation's internal =treefmt= and =nix= overlay groups
participate in this list; caller modules may add their own overlays. The wrapper
provides =devShells.${system}.nix= with =nix-flake-patched= and puts its =bin=
first on =PATH= when entering the shell. It also loads
treefmt-nix and the shared treefmt module. It does not automatically load the
flake-parts =modules= module.

** Formatting defaults
The shared treefmt module provides the flake formatter and enables the formatting
check by default through =lib.mkDefault true=. It derives =projectRootFile= from
the basename of =moduleLocation=, forces treefmt's default excludes off, and
defaults the explicit exclude list to =[ ]=. Unmatched files are fatal, so
consumers must configure exclusions for files outside their formatter coverage.
The root excludes =.gitignore=, =LICENSE=, =README.org=, =flake.lock= and =*.patch=.

| Files | Formatter |
|-------+-----------|
| Nix | nixfmt, width 100, indent 2, strict mode. |
| Shell | shfmt, indent 2, simplification disabled. |
| Prettier-supported files | prettier, width 100, tab width 2, preserved prose wrapping and LF endings. |
| Haskell | fourmolu. |
| Cabal | cabal-fmt; the cabal-project-fmt entry formats project files using =--no-cabal-file --inplace=. |
| XML | xmllint. |
| Python | ruff-format, line length 100. |
| TOML | taplo. |
| Scheme (=.scm=) | =lisplens format=. |
| Emacs Lisp (=.el=) | elisp-autofmt. |

* Provided packages
=legacyPackages.${system}= contains =elisp-autofmt=, =lisplens= and
=nix-flake-patched=. Their
definitions live under =pkgs/pkgs/=, with =overlay.nix= entries assembled by
=lib.packages.mkOverlays=. The two formatter packages provide =nix-update-script=
update scripts.

=elisp-autofmt= installs the upstream Emacs Lisp formatter scripts and configuration,
with a Python command wrapper providing Emacs and Pygments at runtime.
=lisplens= is built with =rustPlatform.buildRustPackage= and provides Lisp formatting
and structural editing commands.

=nix-flake-patched= is a temporary, independent Nix 2.35 package, verified against
2.35.3, for nested relative Flake inputs. Separate patches address
[[https://github.com/NixOS/nix/issues/4811][#4811]] (false circular imports) and
[[https://github.com/NixOS/nix/pull/15982][PR #15982]] / [[https://github.com/NixOS/nix/issues/14762][#14762]]
(wrong source tree when reusing locked inputs). The latter uses upstream commit
=3337ecd3b0ce0dea6200364ccb2afd82f43a692f=, fetched with a fixed hash and filtered
to =src/libflake/flake.cc=. The #4811 patch is maintained locally. Recheck
compatibility when upgrading the base Nix version and remove each patch
separately once its fix is included.
The package does not override =pkgs.nix= or select the system Nix.
Its =passthru.baseNix= exposes the unmodified base derivation, and
=passthru.patches= exposes the ordered patch list. Both are also accessible
directly as =nix-flake-patched.baseNix= and =nix-flake-patched.patches=.

#+begin_src sh
nix build -L .#legacyPackages.x86_64-linux.nix-flake-patched
./result/bin/nix --version
#+end_src

The root also exposes this package as =packages.${system}.nix=. Build it with
=nix build .#nix= and use the resulting =bin/nix= explicitly, or enter the shared
shell with =nix develop .#nix= to use the patched binary on =PATH= for that shell.

The =nix-flake-patched= check builds the
unmodified version, each single patch and the combined package; its first build
can be expensive. It runs offline using private local stores and synthetic
Flakes modeled on the consumer repositories, including their repeated
=path:./pkgs= inputs and =follows=. These tests do not build the real consumers.

The internal =treefmt= group selects =lisplens= and =elisp-autofmt=, while the
=nix= group selects =nix-flake-patched=; neither adds a selection export.
The =legacy= group selects all packages and adds the directory-selected
=legacyPackages= attribute.
The subflake applies =legacy= to its own package set and exports that selection
by system. The root forwards it directly. These overlay groups are internal;
neither flake exports an =overlays= output.

* Shared library
The flake's =lib= output provides functions for use by other repositories.
The filesystem library can also be imported directly with a caller-supplied
Nixpkgs =lib=:

#+begin_src nix
import ./pkgs/lib { inherit lib; }
#+end_src

This direct import provides the merge, overlay, package/module and test helpers;
=mkFlake= is assembled by the subflake and is available through its flake library.

** Recursive attribute-set merge
=lib.mergeAttrsRecursive= takes a named configuration argument followed by a
positional list of non-derivation attribute sets. It recursively merges shared
attribute-set nodes. The configuration argument is required; pass ={ }= to use
the defaults. For example, it can combine repository-level libraries:

#+begin_src nix
inputs.personal-nixpkgs.lib.mergeAttrsRecursive { } [
  inputs.personal-nixpkgs.lib
  inputs.other-project.lib
]
#+end_src

=allowOverrides= must be a boolean and defaults to =false=. Repeated leaves,
including functions, are conflicts even when their values are equal. A leaf and an attribute set
at the same path also conflict. Errors contain the path as a JSON array, and
all overlapping paths are checked before the result is returned.

For example, merging =[ { tools.editor = "emacs"; } { tools.editor = "emacs"; } ]=
in strict mode throws a conflict at =["tools","editor"]= despite equal values.

With =allowOverrides = true=, later list entries take precedence at conflicts;
shared attribute sets still merge recursively:

#+begin_src nix
inputs.personal-nixpkgs.lib.mergeAttrsRecursive { allowOverrides = true; } [
  { a = 1; nested.x = 1; }
  { a = 2; nested.y = 2; }
]
# => { a = 2; nested = { x = 1; y = 2; }; }
#+end_src

A winning leaf replaces the whole lower-priority subtree. For example,
merging =[ { a.x = 1; } { a = 2; } { a.y = 3; } ]= with overrides enabled
produces ={ a.y = 3; }=: the middle leaf replaces the first subtree before the
last entry takes precedence. Derivations are treated as whole leaves.
An empty input list produces ={ }=, and leaves defined by only one input
remain lazy.

** Package and module organization
=lib.packages= discovers overlays and modules from a caller-supplied directory
tree. All functions take an attribute set; paths such as =overlayFile= and
=modulePath= are relative to each discovered directory and have no defaults.

| Function | Arguments | Result |
|----------+-----------+--------|
| =mkOverlays= | =root=, =overlayFile=, optional =extraArgs=, =groups= | Independent top-level directory overlays, or named groups with optional package exports. |
| =mkNixosModule= | =root=, =modulePath= | A module whose =imports= collect the discovered NixOS modules. |
| =mkHomeModule= | =root=, =modulePath= | A module whose =imports= collect the discovered Home Manager modules. |

For example, with this flake available as =inputs.personal-nixpkgs=, a consumer
can construct overlays and select its packages for one system:

#+begin_src nix
let
  helpers = inputs.personal-nixpkgs.lib.packages;
  root = ./pkgs;
  overlayFile = "overlay.nix";
  grouped = helpers.mkOverlays {
    inherit root overlayFile;
    groups = {
      default = { };
      share = {
        exclude = [ "rage-armored" ];
        overlays = [ inputs.git-agent-workflow.overlays.default ];
      };
      legacy.export = true;
    };
  };
  pkgs = import inputs.nixpkgs {
    system = "x86_64-linux";
    overlays = [ grouped.legacy ];
  };
in
{
  overlays = { inherit (grouped) default share; };
  legacyPackages.x86_64-linux = pkgs.legacyPackages;
}
#+end_src

Here, =./pkgs= and =overlay.nix= are consumer choices; =rage-armored= must be a
discovered top-level overlay name, and =git-agent-workflow= is an external flake
input supplied by the consumer. Its overlay participates only in =share=.
The =legacy= group is used internally, while the published =default= and =share=
overlays do not add a package export.

*** Overlay groups and package exports
With =groups= omitted or ={ }=, the result retains the independent overlays named
after immediate child directories containing an overlay or descendant overlays.
With nonempty =groups=, each result is a standard overlay. It first applies
external overlays in list order, then the selected local overlays in attribute-name
order, and finally its optional export extension. All groups share one lazy
directory description per =mkOverlays= call.

Each group accepts these fields:

| Field | Type | Default |
|-------+------+---------|
| =include= | List of local overlay names. | All names from the existing local discovery result. |
| =exclude= | List of local overlay names. | =[ ]=. |
| =overlays= | List of external overlay functions. | =[ ]=. |
| =export= | Boolean or nonempty string. | =false=. |

Local selection first includes the named overlays, then removes excluded names.
For example, =include = [ "lisplens" ]= selects only that discovered overlay;
=include = [ ]= selects no local overlays. Omitting =include= retains the existing
all-local-overlays behavior. An excluded name may lie outside =include= as long as
it exists in local discovery. Exclusion wins when a name appears in both lists.
Neither list controls composition order, and duplicate names do not cause an
overlay to be applied twice. Both lists reject unknown names and empty directories
without discovered overlays. Their defaults reuse discovery without another scan.

=include= and =exclude= affect only local overlays and their export paths.
They do not filter external =overlays= or prohibit other overlays from creating
attributes at unselected names. External overlays remain active even when all
local overlays are omitted or excluded. Unselected local constructors are not
imported or instantiated merely for discovery or configuration validation.
Each group's external overlays and selection are independent of other groups.

=export = true= adds =legacyPackages=; a nonempty string uses that export name
instead. =false= adds no export. Groups and individual configurations must be
attribute sets; invalid field types, unknown fields and empty export names are
errors. Export paths come only from the selected local directory tree. Packages
added solely at other paths by external overlays are not automatically exported.
With no selected local overlays, an enabled export produces an empty tree even
when external overlays add packages.

Exports are added by the group's last extension. Its =prev= includes the group's
external and local overlays and must not already contain the export name;
conflicts with upstream attributes, external overlays or the group's local
definitions fail instead of overwriting.
The selector reads =final=, so a later overlay's package replacements appear in
the export. Selecting packages never reapplies overlays. Group overlays are
alternatives; do not apply both =default= and =legacy= to the same package set
unless intentionally applying their shared base overlays again.

*** Overlay conventions
Discovery starts with the children of =root=. An overlay file directly inside
=root= is not loaded. Every definition loaded by the aggregator is an overlay
constructor. A definition with no construction dependencies uses:

#+begin_src nix
{ }:
final: prev: {
  example = final.callPackage ./package.nix { };
}
#+end_src

The constructor returns a standard two-argument Nixpkgs overlay; its returned
attributes determine package names at that level. Existing two-argument source
files must add the constructor layer. Overlays returned by =mkOverlays= remain
standard two-argument functions and are consumed normally by Nixpkgs.

=mkOverlays= accepts =extraArgs ? { }= as a constructor environment. For example:

#+begin_src nix
helpers.mkOverlays {
  inherit root overlayFile;
  extraArgs = { inherit inputs; };
}
#+end_src

A source can receive this environment explicitly and forward selected values:

#+begin_src nix
{ extraArgs }:
final: prev: {
  example = final.callPackage ./package.nix {
    source = extraArgs.inputs.example;
  };
}
#+end_src

Only =extraArgs= and =descendantOverlay= may be explicitly declared in the
constructor parameter set. Unknown names are errors. Only declared parameters
are supplied, including those with defaults. ={ ... }:= is accepted, while
={ }:= is preferred when no parameters are needed. Standard overlay parameters
may still destructure =final=; constructor name validation applies only to the
first function layer. As with ordinary Nix overlays, destructuring =final=
forces that value and may cause recursion when constructing a fixed point.

The same environment reaches nested constructors and factory-owned descendants.
Unused environments and members remain lazy. Parameters are captured by lexical
closure; the aggregator does not add them to =pkgs=, =final=, =prev= or the
=callPackage= environment. Package arguments must be forwarded explicitly.

Descendant overlays are grouped under the containing directory's name as a
package namespace. Existing scopes are extended through =overrideScope=;
ordinary attribute sets and new namespaces use =lib.makeScope= and require
the parent package set to provide =newScope=. A namespace cannot replace a
derivation or a non-attribute value.

A constructor declaring =descendantOverlay= owns its descendants. It can use
={ descendantOverlay }:= or ={ extraArgs, descendantOverlay }:=. It receives
the composed descendant overlay and takes responsibility for applying it; automatic namespace handling of those descendants is skipped.
Declaring only =extraArgs= does not take ownership. Explicit definitions and
implicit rules use the same constructor protocol. Within a level, local overlays
are composed before automatic namespace overlays.

When an immediate child of =root= has descendant overlays but no explicit
=overlayFile=, =mkOverlays= selects a built-in rule by its directory name:

| Directory | Default behavior |
|-----------+------------------|
| =emacsPackages= | Extend each =emacsPackagesFor emacs= scope through =overrideScope=; the factory owns the descendants. |
| =texlivePackages= | Aggregate the namespace normally and expose its packages through the existing TeX Live selection interfaces. |
| Other names | Use the generic namespace behavior above, including =piPackages=. |

Explicit parent overlays always take precedence. An ordinary explicit overlay
still composes with descendant namespace aggregation; an explicit factory owns
the descendants. Empty directories do not produce overlays, and special names
nested below the immediate children do not select built-in rules. The filename
is always the caller's =overlayFile=, not necessarily =overlay.nix=.

The TeX Live rule wraps =texlive.withPackages=, =texlive.combined=, and the
previously supported top-level =texlive*= environments. It preserves support
for newly named packages from other overlays. Packages declared by the current
=texlivePackages= directory also override same-name packages in selection
callbacks. Selected replacements are passed to the environment builder;
prebuilt environments are not rebuilt automatically without using a selection
entry point. Other overlays' same-name replacements are not explicitly forwarded
by this rule. Internal rules are not exposed as additional public library APIs.

Group exports preserve namespace nesting and select derivations at leaf
directories with overlay files. Missing or non-derivation leaves are skipped.
Paths with descendant overlays must exist as non-derivation attribute sets;
missing namespaces, derivations with descendants and other namespace values
are errors. Extra attributes returned by overlays are not exported unless a
directory selects them. Factories retain the same directory-to-attribute mapping;
arbitrary relocation is not inferred. Emacs exports use the final =emacsPackages=
namespace, and TeX selection reuses the shared =texlivePackages= subtree.

*** Module conventions
=mkNixosModule= and =mkHomeModule= use the same discovery mechanism. For example:

#+begin_src nix
helpers.mkHomeModule {
  root = ./pkgs;
  modulePath = "home-module.nix";
}
#+end_src

The helper recursively searches child directories for the chosen =modulePath=.
A directory with such a module must not also contain matching modules in its
descendants. The module file directly inside =root= is not included.

** Test organization
=lib.tests= shares the directory-based overlay aggregation mechanism used by
=lib.packages=, without package-specific defaults. Its public entry is =mkChecks=:

| Function | Arguments | Result |
|----------+-----------+--------|
| =mkChecks= | =root=, =overlayFile=, optional =checks=, =args=, =separator= | Existing checks extended by test overlays, plus flattened directory-selected derivations. |

=mkChecks= discovers and composes the overlays internally, constructing an
independent test scope. Test overlays are an internal organization mechanism;
there is no public overlay discovery interface in =lib.tests=. Test overlays do
not extend =pkgs=. Test source files use the same constructor protocol, including
={ }: final: prev: { ... }=. Their constructor =extraArgs= defaults to ={ }=;
=mkChecks.args= supplies scope dependencies and is not mapped to that environment.
For example:

#+begin_src nix
llib.tests.mkChecks {
  root = ./tests;
  overlayFile = "test-overlay.nix";
  checks = existingChecks;
  args = {
    inherit pkgs llib;
    inherit (pkgs) writeText;
  };
}
#+end_src

=checks= defaults to ={ }= and supplies existing check names to preserve.
=args= defaults to ={ }= and supplies dependencies to the test scope and its
=callPackage=. Dependencies such as =writeText= must be passed explicitly;
passing =pkgs= does not implicitly inject its members. Initial checks take
precedence over same-named arguments. Standard overlay semantics apply: =prev=
sees earlier definitions, =final= sees the final test scope, and later overlays
can replace existing checks. Existing names are read from the final definitions
and must remain derivations, even when no corresponding directory exists.

Arguments are not automatically exported, including derivation-valued helpers.
The output includes final values for existing check names and flattened
directory-selected derivations (the latter win if output names coincide).
There are no special directory roles or test runner.

Scope resolution and =callPackage= can supply dependencies from other directories
without parent-directory imports. The chosen =root= and =overlayFile= determine
discovery; keep overlay fixtures under test outside that discovery scope, or use
a different filename. The root's own overlay file is ignored.

=mkChecks= traverses the directory tree, using the assembled test definitions
for values at the corresponding paths. It does not enumerate arguments to find
extra checks:

| Discovered directory | Corresponding scope value | Action |
|----------------------+---------------------------+--------|
| Leaf with an overlay | Derivation | Extract it. |
| Leaf with an overlay | Missing or non-derivation | Skip it. |
| Leaf with an overlay | Ordinary attribute set | Skip it without traversing its attributes. |
| Has descendant overlays | Non-derivation attribute set | Continue along the directory tree. |
| Has descendant overlays | Missing, derivation, or other value | Report an invalid namespace path. |

Directories with no matching overlay or descendant overlays are ignored.
The internal scope may contain helper functions, evaluation results and other
values; only existing check names and directory-selected derivations are
exported. Factory ownership of
=descendantOverlay= does not provide a path mapping to =mkChecks=. If a factory
relocates results, the caller must arrange their export.

The optional =separator= defaults to ="/"=. A selected derivation at
=packages.aggregation= in the assembled definitions becomes the flat check
="packages/aggregation"=.
Passing =separator = "-"= or =separator = "."= changes that name to
="packages-aggregation"= or ="packages.aggregation"=. Callers are responsible
for name collisions introduced by their chosen separator.

* Tests
=tests/default.nix= accepts ={ llib, lib, pkgs, nix-flake-patched }= and returns the
complete check derivation set. Ordinary suites live under =tests/suites/=, each
with a =cases.nix= expression, a =test-overlay.nix= entry, and any local fixtures.
The functional =nix-flake-patched= suite instead has a check wrapper, fixture
specification and Python runner embedded in Nix files. Its explicit
=nix-flake-patched= argument is the package derivation supplied by the root.
The suite reads its base Nix and patch paths from the package's =passthru=
metadata. Its overlay explicitly supplies =prev.nix-flake-patched= to the check
wrapper because the check has the same name as the package argument; this avoids
resolving the argument to the check itself through the final test scope.
The entry passes existing API checks and shared arguments to =lib.tests.mkChecks=,
which builds the test scope, applies discovered overlays, and extracts checks.
=callPackage= supplies each report wrapper's arguments;
the wrapper evaluates its local cases and uses the shared =mkResultCheck= helper
to produce a JSON derivation.

The discovery filename is =test-overlay.nix=, so fixture =overlay.nix= files do
not become suite entries. This layout and filename are repository conventions,
not special roles in the public API. Cross-parent-directory dependencies must
be passed as function parameters or through scope; parent-directory imports
and equivalent ancestor traversal are forbidden.

The =mergeAttrsRecursive= suite contains 43 evaluation cases covering recursive
merging, strict conflicts, later-entry override precedence, subtree replacement,
function and list values, derivation-shaped leaves, input validation, and
laziness. It returns named boolean results on success and reports failed case
names in an error. The derivation cases do not build real packages.

The =overlays= suite tests the shared internal aggregator independently of
package-specific rules: discovery, ordinary overlays and factories, implicit-rule
precedence, scope dependency resolution, namespace collisions, and custom overlay
filenames. It calls =llib.overlays.mkOverlays= through the subflake library.
The package API supplies its domain rules to that same aggregator.

The =packages= suite covers implicit and explicit rule selection, namespace and
module discovery, package extraction, scope dependency resolution, and TeX
addition/replacement forwarding. Group cases cover include/exclude selection,
external-overlay ordering and isolation, directory-constrained exports, constructor
laziness and invalid configurations. It uses small evaluation fixtures on all
systems, with additional real Emacs and TeX package-set evaluation on
=x86_64-linux=. It does not build large editor or TeX environments.

The =testApi= suite verifies the public test helpers with independent fixtures,
including scope dependencies, extraction boundaries, separators and factory
paths. Three extracted =pkgs.writeText= checks under =testApi/= are also built
through the flake. The API suite and these real checks are supplied as existing
=checks= at the root, independently of ordinary-suite discovery. The root also requires
the complete output names to match the existing API checks plus =mergeAttrsRecursive=,
=overlays=, =packages= and =nix-flake-patched=, so missing or unexpected checks
fail evaluation.
Adding an ordinary suite also requires updating this expected-name set.
Existing aggregation assertions and report/check names are retained; API tests
track the current assembly and extraction contract.

Run the merge suite alone from the repository root without loading flake inputs:

#+begin_src sh
nix-instantiate --eval --strict --readonly-mode \
  --expr 'import ./tests/merge-attrs-recursive.nix { llib = import ./pkgs/lib { lib = {}; }; }'
#+end_src

The merge suite needs no Nixpkgs library functions, so this command supplies
an empty =lib=. The package suite uses the flake's locked Nixpkgs.
The root separately imports that Nixpkgs for the test entry's =pkgs= argument,
without the project's overlays. Real package-set fixtures can therefore append
their own export-enabled overlays without colliding with a project-level
=legacyPackages= attribute. The test entry's =lib= argument is supplied from the
enclosing per-system package set.

The flake injects the shared dependencies into the test entry and exposes its
returned checks directly, alongside the formatting check. Failed suites stop
evaluation; successful evaluation suites produce a JSON report of the named
results. Extracted check derivations are included directly.
Run all checks for the current system with =nix flake check=, or build the
merge suite's report directly:

#+begin_src sh
nix build .#checks.x86_64-linux.mergeAttrsRecursive
nix build .#checks.x86_64-linux.packages
nix build .#checks.x86_64-linux.overlays
nix build .#checks.x86_64-linux.testApi
#+end_src
